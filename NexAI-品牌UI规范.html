01 · EXPERIENCE PRINCIPLES

NexAI 的产品体验原则

先统一底层逻辑，再统一页面。任何扩展都应该帮助用户把真实行动沉淀为可理解、可复核、可连接机会的成长证据。

结果先于功能

首屏先说明用户会完成什么、证明什么，再解释模块和工具。

真实工作而非刷课

学习必须通向项目、交付物、决定或可演示能力。

证据而非装饰

来源、贡献、复核状态和时间是信息，不是庆祝型徽章。

用户保持控制

连接账号、上传、外部提交和公开分享都由用户主动触发。

渐进式披露

默认界面保持平静，目录、产物、证据和工具按需展开。

高信任有人负责

AI 可预审，但正式认证与高风险结论需要具名人工评审。

统一价值闭环真实任务 → 可检查交付物 → 过程证据 → 反馈 / 人工复核 → 我的 AI 护照 → 项目或岗位机会
02 · COLOR SYSTEM

颜色是语义，不是装饰

白色与灰色构成产品空间，紫色负责身份与行动，橙色只表达时间性和增长动能。

05 · PAGE PATTERNS

先选页面模式，再画页面

外部参考只提供拓扑或交互启发，不能覆盖 NexAI 的命名、证据模型、品牌和可信边界。

首页聚合

Banner → AI护照 → PBL实战项目 → 精选活动 → 专业认证 → 机会。首页只承担发现与导航，不复制详情页。

项目详情

沉浸式暗色 Hero、项目信息、开始实战、媒体面板、交付/证据/复核，以及桌面端粘性摘要。

AI 项目跟练室

左侧教学与任务，中间 Codex 式操作画布，右侧预览/文件/证据默认收起。操作前中间保持空白。

我的 AI 护照

宽屏自由拖拽缩放，中屏与移动端切换为可读单列；系统 AI 能力卡不可删除，证据等级必须可区分。

社区

羊皮纸灰工作区、白色内容卡、聚焦信息流与右侧推荐，不恢复冗余内部频道栏。

专业认证

职业结果 Hero → 证明条 → 学习体验 → 模块 → 实战项目 → 考核与人审 → 证书 → 相关岗位。

07 · CROSS-FUNCTION WORKFLOW

产品、设计和前端如何共同使用

同一份规范需要在决策、视觉和实现三个层面落地。

产品经理
  1. 定义用户结果与主行动
  2. 明确交付、证据和复核
  3. 选择现有页面模式
  4. 区分事实、假设和市场数据
  5. 写清跨端验收标准
UI / 产品设计
  1. 从令牌和模式开始
  2. 用真实中文内容校验密度
  3. 补齐交互和异常状态
  4. 控制紫色与卡片数量
  5. 同时交付桌面、中屏、移动
前端工程
  1. 复用现有组件与资产
  2. 保持路由和运行时结构
  3. 实现完整主要流程
  4. 显式实现响应式转换
  5. 构建、浏览器、控制台和视觉验收
08 · CONTENT & TRUST

设计也要对声明负责

能力、认证、岗位和 AI 行为都必须可解释。高信任并不来自更醒目的徽章，而来自来源、标准和责任人。

必须做到

  • 说明真实任务和可检查交付物
  • 区分自述、来源链接、过程证据、复核与认证
  • 公开考核标准和人工评审角色
  • 岗位数据标明会随市场变化
  • 账号连接、上传和公开分享由用户主动决定

禁止偏差

  • 把 AI 预审写成正式认证
  • 把 GitHub 链接写成原创证明
  • 声称国际标准认证或大学学位等价
  • 承诺岗位、录用或固定薪资
  • 暗示系统自动读取外部账号或私有资料

09 · SHARED QA GATE

共同验收，不靠感觉签收

更完整的逐项清单见 references/qa-checklist.md。

  • 首屏能清楚表达用户结果和主行动
  • 官方 Logo 未被重绘、压缩或错误着色
  • 紫色、橙色、圆角和边框符合语义
  • 没有装饰性渐变与例行卡片阴影
  • 主要正文在桌面和移动端可读
  • 核心按钮、Tab、输入和折叠状态真实可用
  • 宽屏、中屏、移动端均无横向溢出
  • 证据等级、人工评审与隐私授权表达准确
  • 构建与相关测试通过
  • 浏览器检查主流程且控制台无新增错误
  • 参考图与实现做同视口组合比较
  • 未获授权前不发布、不提交、不改变外部状态
