# NexAI Shared QA Gate

Do not hand off a NexAI page as complete until the applicable items pass.

## A. Product and content

- [ ] One primary user outcome is clear above the fold.
- [ ] One primary action is visually dominant in each major region.
- [ ] The flow leads to a real deliverable, decision, or next step.
- [ ] User-facing naming matches the current IA: AI护照 / 项目 / 社区 / 机会.
- [ ] Facts, assumptions, market data, and future capabilities are distinguishable.
- [ ] No unsupported accreditation, authorship, partnership, salary, or employment claim.
- [ ] Certification and other high-trust conclusions include a human review path.

## B. Brand and visual system

- [ ] Official NexAI logo asset is reused and undistorted.
- [ ] Purple is limited to identity, active state, evidence emphasis, and the primary action.
- [ ] Orange is used only for urgency/growth momentum.
- [ ] No decorative UI gradients were introduced.
- [ ] Routine cards use borders/spacing rather than shadows.
- [ ] Radii match control/card/panel hierarchy.
- [ ] The page does not become an undifferentiated grid of cards.
- [ ] Icon family is Phosphor and stroke weights are consistent.

## C. Typography and readability

- [ ] Chinese headline wraps intentionally at desktop and mobile.
- [ ] Primary body copy meets the minimum readable sizes.
- [ ] Dense 8–10px metadata is not used for primary explanation.
- [ ] Line height is sufficient for Chinese paragraphs.
- [ ] Text contrast passes WCAG AA.
- [ ] Real content has been used to test wrapping and truncation.

## D. Components and interactions

- [ ] Default, hover, focus-visible, pressed, disabled, and selected states exist where relevant.
- [ ] Core visible controls work; they are not static decoration.
- [ ] Tabs use accessible roles and selected state.
- [ ] Icon-only buttons have accessible names.
- [ ] Inputs have labels and clear focus/error/success behavior.
- [ ] Consequential AI or external actions explain what happens and request confirmation when needed.
- [ ] Expanded/collapsed states follow progressive disclosure.

## E. Layout and responsiveness

- [ ] Wide desktop checked.
- [ ] Intermediate desktop/tablet checked.
- [ ] Mobile checked at 390px or similar.
- [ ] No horizontal overflow.
- [ ] Persistent controls remain reachable.
- [ ] Multi-column content becomes a readable single-column flow where appropriate.
- [ ] Mobile actions stack/full-width when needed.
- [ ] Free drag/resize is disabled in non-freeform responsive modes.

## F. Evidence and privacy

- [ ] Evidence states distinguish self-report, linked source, reviewed, and certified.
- [ ] Provenance, contribution, mastery, and impact are not collapsed into one score.
- [ ] AI assistance and collaborator roles can be represented.
- [ ] User controls account linking, uploads, external submission, and public sharing.
- [ ] Formal certification is not produced automatically by AI.

## G. Engineering verification

- [ ] Existing runtime/routes/build files preserved.
- [ ] Build succeeds.
- [ ] Relevant tests succeed.
- [ ] Local route opened in the selected browser.
- [ ] Primary interactions tested in the browser.
- [ ] Browser console has no errors/warnings introduced by the change.
- [ ] Visual screenshot inspected at desktop and mobile.
- [ ] If matching a reference, source and implementation were compared in one combined view.

## H. Final handoff

- [ ] Working preview or artifact path supplied.
- [ ] Files changed are named.
- [ ] Verification result is stated without overclaiming.
- [ ] Remaining assumptions/P3 polish are listed.
- [ ] No deployment or production publication occurred without explicit authorization.
